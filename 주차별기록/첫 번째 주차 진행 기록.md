## 1주차

### 이번 주에 한 일

이번 주에는 프로젝트의 기본 기능인 **Google Gemini API 기반 CLI AI 챗봇**을 구현했다.

사용자가 콘솔에 입력한 질문을 Gemini API에 전달하고, 생성된 답변을 받아 콘솔에 출력할 수 있도록 기본적인 채팅 구조를 구성했다. 프로그램의 기능을 구분하기 위해 사용자 입력과 종료 명령을 처리하는 부분, Gemini API를 호출하는 부분, 환경 설정을 읽는 부분, 대화 기록을 관리하는 부분을 각각 별도의 파일로 나누었다.

API Key와 사용할 Gemini 모델은 코드에 직접 작성하지 않고 프로젝트 최상위 폴더의 `.env` 파일에서 읽도록 구성했다. API Key가 Git 저장소에 올라가지 않도록 `.gitignore`에도 `.env`를 추가했다.

일반 대화뿐만 아니라 코딩 관련 질문, 내용 요약, 개념 설명, 짧은 문장 번역 요청도 동일한 채팅 입력을 통해 Gemini에 전달할 수 있도록 구현했다. 이러한 기능을 각각 별도의 함수로 만든 것은 아니며, Gemini가 사용자의 자연어 요청을 이해하여 답변하도록 구성했다.
;';.'.'''
짧은 문장이나 채팅 중 필요한 간단한 번역은 일반 챗봇이 처리하도록 했다. 이는 다음 주에 구현할 Local LLM 기반 TXT 파일 일괄 번역 기능과 분리되는 기능이다.

또한 이전 사용자 메시지와 Gemini의 답변을 메모리에 저장하고, 다음 요청에 기존 대화 기록을 함께 전달하도록 구현했다. 이를 통해 사용자가 이전 내용을 다시 구체적으로 설명하지 않고 “그 내용을 쉽게 설명해 줘”와 같이 질문해도 앞의 대화를 참고할 수 있는 구조를 만들었다.

사용자가 `/clear`를 입력하면 현재 대화 기록을 초기화하고, `/exit` 또는 `exit`를 입력하면 프로그램을 정상적으로 종료하도록 했다. API Key 누락, 네트워크 연결 실패, API 요청 실패, 잘못된 응답 형식, 빈 답변 등이 발생한 경우에도 오류 내용을 출력한 뒤 다시 질문을 입력할 수 있도록 예외 처리도 추가했다.

마지막으로 실제 Gemini API를 호출하지 않고도 설정 읽기, 메시지 전달, 대화 기록 유지, Gemini 요청 형식, 오류 처리, 종료 및 초기화 명령을 확인할 수 있는 단위 테스트를 작성했다.

### 새롭게 알게 된 것

LLM API를 이용한 챗봇은 현재 사용자가 입력한 질문만 전달하는 것이 아니라, 이전 사용자 메시지와 AI 답변을 함께 전달해야 앞의 내용을 참고하는 자연스러운 대화가 가능하다는 점을 알게 되었다.

Gemini API에서는 대화 메시지를 `user`와 `model` 역할로 구분하며, 챗봇의 기본 동작을 알려 주는 시스템 메시지는 별도의 시스템 지시 항목으로 전달해야 한다는 점을 확인했다. API마다 요청 메시지와 응답 데이터의 구조가 다르므로 사용하는 API의 형식에 맞게 데이터를 변환하는 과정도 필요했다.

또한 API 호출 부분과 실제 채팅 동작을 분리해 두면 모델이나 API 요청 방식이 변경되더라도 사용자 입력, 대화 기록, 명령 처리 부분을 그대로 활용할 수 있다는 점을 알게 되었다.

번역 역시 별도의 번역 기능을 반드시 호출해야 하는 것은 아니며, 짧은 문장 번역 정도는 LLM이 일반 채팅 과정에서 사용자의 요청을 이해하여 처리할 수 있다는 점도 확인했다.

### 어려웠던 점

Gemini API가 요구하는 요청 형식에 맞춰 사용자 메시지, 모델 메시지, 시스템 지시를 구분하고, 이전 대화 기록을 올바른 순서로 전달하는 구조를 구성하는 부분이 어려웠다.

처음에는 `main.py`를 직접 실행했을 때 프로젝트의 `script` 패키지를 찾지 못해 `ModuleNotFoundError`가 발생했다. 직접 실행하는 방식과 모듈로 실행하는 방식에서 Python의 모듈 검색 경로가 다르다는 점을 확인했고, 두 실행 방식 모두 사용할 수 있도록 실행 진입점을 수정했다.

실제 Gemini API 요청 과정에서는 선택한 모델의 사용량이 많아 HTTP 503 오류가 발생하기도 했다. 이는 프로그램 코드의 오류가 아니라 Gemini 서버의 일시적인 과부하로 발생한 문제였으며, 이러한 API 오류가 발생해도 프로그램이 종료되지 않고 다시 입력을 받을 수 있도록 처리했다.

대화 기록을 계속 추가하면 이전 대화를 참고할 수 있지만, 대화가 길어질수록 API에 전달하는 데이터도 많아진다. 현재는 1주차 범위에 맞게 전체 대화를 메모리에 유지하지만, 이후에는 기록의 길이를 제한하거나 필요한 대화만 전달하는 방법을 고려할 필요가 있다.

또한 API Key와 모델 설정이 없거나 잘못된 경우, 네트워크 연결에 실패한 경우, Gemini가 정상적인 답변을 반환하지 않은 경우를 각각 구분하여 사용자가 이해할 수 있는 오류 메시지를 출력하는 예외 처리가 필요했다.

### 다음 주에 할 일

다음 주에는 일반 챗봇과 별도로 **Local LLM 기반 TXT 파일 일괄 번역 기능**을 구현할 예정이다.

사용자가 지정한 폴더에서 `.txt` 파일을 자동으로 찾고, 각 파일의 내용을 읽어 Local LLM에 전달한 뒤 번역 결과를 별도의 출력 폴더에 저장할 계획이다.

여러 개의 파일이 존재하는 경우 파일을 순서대로 처리하고, 원본 파일명은 유지하면서 원본 파일과 번역 결과 파일을 구분하여 관리할 예정이다. 또한 번역 진행 상태를 확인할 수 있도록 하고, 특정 파일의 번역에 실패하더라도 나머지 파일 처리를 계속할 수 있는 구조를 구성할 계획이다.

원본 언어와 목표 언어 설정, 문서 종류에 따른 번역 규칙, Prompt Preset 저장 및 불러오기 기능은 파일 일괄 번역 기능을 구현한 이후 3주차에 추가할 예정이다.
